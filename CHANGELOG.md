# Changelog

## Unreleased (0.5.0)

- **Breaking** (security default, provenance by default): `AtlasPca.authorize` (and so the Rack middleware's `authorize:` path, `AtlasPca.protect` and the executor) runs a new check, `provenance_flow`, on every call. A sensitive operation (any action your facts do not mark read-only; an unknown action is sensitive) whose choice or arguments do not derive from the principal is `escalate`: `provenance_flow: escalate: <values> derive from untrusted content [<path>]: the principal must confirm (prompt-injection path)`. A missing bundle, or one from a mediator you do not pin, counts as untrusted; a forged chain is a `deny` (`provenance_flow: <code>: <reason>`). Migration: pin your agent harness with `provenance: { mediators: [{ "mediator", "kid", "pk" }] }` and have it present the bundle (header `PCA-Provenance`, body member `pca_provenance`, or `provenance_bundle:`); an operation straight from your own UI uses `AtlasPca.principal_direct_provenance`. The only opt-out is the principal-signed grant envelope member `provenance: { mode: "insecure_off" }` (reported `not-enforced`; dangerous). An executable plan from `plans:` and an admitted `workflow` step count as the principal's choice. New public API: `decide_arg_provenance`, `occurs_as_token`, `prov_leaves`, `read_only_action?`, `prov_receipt_wire_error`, `prov_action_info_error`, `prov_envelope_error`, `prov_action_digest`, `prov_receipt_ref`, `default_provenance_bundle`, `provenance_flow_check`, `AtlasPca::ProvenanceRecorder` (`principal`, `tool`, `retrieval`, `web`, `for_action`, `pin`) and `principal_direct_provenance`; `mint_grant` accepts the envelope member `provenance`; `AuthorizeOptions` gains `provenance`. Replays `arg-provenance-vectors.json` (`test/test_arg_provenance_vectors.rb`, `test/test_provenance_flow.rb`).
- **New (undo windows):** the pure layer of reversible-action veto windows: `compensation_digest`, the one-click undo token (`sign_undo_token`, `undo_token_check` with the codes `malformed`, `signer`, `signature`, `record`, `binding`, `expired`; valid through `exp`), `encode_undo_token` / `decode_undo_token` / `undo_token_digest`, signed receipts (`sign_undo_receipt`, `verify_undo_receipt`, `undo_receipt_digest`, `undo_receipt_chain_error`, `undo_with_receipt`), the state machine `undo_transition`, `resolve_undo_window` (30 s .. 24 h, default 15 min) and the obligation kind `undo_window` {id, window_end} (`undo_window_obligation`). `AtlasPca.authorize(..., undo: ->(pcactn, grant, operation) { admission | nil })` (and `AuthorizeOptions#undo`, the middleware's `authorize: { undo: }`) lets an unanswered escalation run now under a veto window: the call is allowed, `result.undo` is the admission and `result.obligations` carries the `undo_window` obligation. Never for a provenance escalation (`provenance_flow` or `provenance`), never when an escalation answer is presented, never for a deny; a raising or malformed hook leaves the escalation. Replays `undo-vectors.json` (`test/test_undo_vectors.rb`).

- **New (developer experience):** `AtlasPca.protect(audience:, grants:, operation:, ...)` returns the `AtlasPca::RackMiddleware` options with secure defaults (grants looked up from your list or callable, never the request; a `MemoryStateStore` for replay; a revocation source; `plan: 'single-step'`) plus `revoke(grant_id)`. Options you pass win. Not ported: the TypeScript catalog risk (`authorize` has no `risk` option here). `AtlasPca.explain_refusal(reason)` returns the meaning, fix and docs page of a refusal reason (same table as the TypeScript `explainRefusal`; the reasons themselves are unchanged). Every 401 and 403 body from the Rack middleware gains a `doc` member (the refusals page, anchored at the refusing check); existing members and reason strings are unchanged, so a client that compares the whole body must allow the new member. A runnable server example lives in `examples/rails-server`. Tests: `test/test_protect.rb`.
- **New (native signing, agent side):** `lib/atlas_pca/agent.rb`, the producer half of the gem, so an agent never needs a TypeScript process: `AtlasPca::KeyPair`, `mint_grant` (envelope, salted goal commitment, `holder_pq`), `delegate_cap` / `attenuate_cap` (append-only caveats; `sealed_caveat`, `max_uses_caveat`, `needs_discharge_caveat`), `commit_plan` with Merkle proofs, `build_pcactn` (signed `aud`/`iat`/`exp`/`nonce`, optional signed slots), `pca_headers`, `sign_escalation_answer`, `sign_discharge`, `sign_narrow`, `issue_passport` / `sign_passport`, `sign_workflow` / `sign_step_receipt`, `sign_read_grant`, `sign_aggregate_grant`, `sign_fresh_at` and the `AtlasPca::Agent` client (`act`, `delegate`, `use_plan`: counter, nonce and header handling). With OpenSSL >= 3.5, ML-DSA / SLH-DSA and their hybrid and nested-hybrid suites sign through `PqKeyPair`; fn-dsa-* and less-cat1 are verify-only (`UnsupportedSigner`); CI signs and cross-verifies ML-DSA and SLH-DSA on OpenSSL 3.5. Deterministic outputs reproduce `producer-vectors.json` byte for byte (`test/test_agent_producer.rb`, which also round-trips every artifact through the verifiers).

- **Breaking** (K5 security default flip): `plan_root_authorized` is enforced by default. With no plan and no authorization configured, `AtlasPca.authorize` now FAILS the check with `plan_root_authorized: default-deny: no authorized plan is configured for this verifier (supply the plan and its authorization, or set insecure_skip_plan_root_check)` instead of reporting `not-enforced`. `authorize` accepts no opt-out (the explicit `insecure_skip_plan_root_check` of the lower-level verifier is not offered by this pipeline). Pass `plan: 'single-step'` or a context plan with `plan_authorized: true`.

- **New (K5 workflow, order and middleware):** `AtlasPca::RackMiddleware.new(..., workflow: {principal:, rs_signer:, required:}, workflow_step: ->(env){...})` forwards the workflow gate to `authorize` (and the executor path). The step comes from `workflow_step:` or the JSON body member `workflow`. Required and no step is a 403 (`workflow: this call carries no workflow step (fail closed)`) before the PCActn is read. `authorize` now matches the TS order: a workflow step with an undecodable PCActn skips the gate and gets the pipeline's own 401; an undecodable (present, unreadable) PCActn is now check `pcactn`, reason `undecodable PCActn: ...` (was `wire`; an absent one stays `wire: no PCActn presented`). Tests: `test/test_middleware_workflow.rb`.
- **New (K5 closing gaps):** `AtlasPca.authorize(..., workflow: {principal:, rs_signer:, required: false}, workflow_call: {commitment:, receipts:, step:, units: {}, goal_digest: nil})` admits the call's workflow step (`admit_step`, with the operation, the PCActn's plan root and the call's `now`) BEFORE any verification or replay state, so a refusal never consumes the counter: failing check `workflow`, status 403, reason `workflow: <code> (step <id>)`; an `escalate` result keeps `decision: 'escalate'` (`allow` false); a missing call is refused when `required` and unchanged otherwise. Replays `authorize-workflow-fixtures.json` (`test/test_authorize_workflow.rb`). Also the tokenisation vault and aggregate reads: `memory_vault`, `redact_read_with_vault`, `detokenize`, `aggregate_read` (k floor, clamp, query cap, integer micro-epsilon budget, repeated query answered without a charge, integer-exact discrete Laplace sampler `seeded_draws` / `discrete_laplace`; `noise: 'secure'` draws its seed from the OS CSPRNG, the production setting). Verification only (no grant signing). Replays `vault-aggregate-vectors.json` (`test/test_k5_vault.rb`).
